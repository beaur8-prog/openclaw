# CRON_VS_HEARTBEAT.md

## 개요

이 환경에서 `cron`과 `heartbeat`는 둘 다 주기적으로 무언가를 수행한다는 점은 같지만, 설계 의도와 실행 방식이 다르다.

- `cron`: 정해진 시간에 독립적으로 실행되는 예약 작업
- `heartbeat`: 에이전트가 주기적으로 주변 상태를 점검하는 운영 루틴

한마디로 정리하면:

- `cron`은 "언제 실행할지"가 중심이다.
- `heartbeat`는 "지금 점검할 게 있는지"가 중심이다.

## Cron

`cron`은 정해진 시각이나 간격에 자동으로 특정 작업을 실행하는 스케줄러다.

이 저장소에서는 `cron/jobs.json`에 작업이 등록되어 있고, 각 작업은 아래 요소를 가진다.

- `expr`: 크론 표현식
- `tz`: 시간대
- `payload`: 에이전트에 전달할 작업 지시
- `delivery`: 결과를 어디로 보낼지
- `state`: 최근 실행 성공/실패 상태

### 특징

- 시각 조건이 명확하다.
- 사용자가 말을 걸지 않아도 독립적으로 실행된다.
- 실행 결과가 로그로 남는다.
- 외부 채널 전달까지 포함할 수 있다.
- 실패 횟수와 마지막 상태를 추적한다.

### 이 프로젝트에서의 예

`cron/jobs.json`에는 이런 작업들이 들어 있다.

- 매일 아침 AI 뉴스 브리핑 생성
- 미국장 아침 브리핑 생성
- 업비트 라이브 상태 점검
- BTC 변동성 알림
- 업비트 체결 시 그래프 포함 알림

즉 이 프로젝트에서 `cron`은 단순 셸 스케줄러가 아니라, "예약된 에이전트 실행기" 역할을 한다.

## Heartbeat

`heartbeat`는 엄격한 시각 예약보다 "주기적 확인"에 가까운 메커니즘이다.

이 개념은 `workspace/AGENTS.md`와 `workspace/HEARTBEAT.md`에 설명되어 있다. 목적은 에이전트가 정기적으로 주변 상태를 살피되, 매번 사용자에게 말 걸지 않고 필요한 경우에만 반응하는 것이다.

### 특징

- 정확한 시각보다 주기적 점검이 중요하다.
- 여러 점검을 한 번에 묶을 수 있다.
- 결과가 없으면 조용히 끝낼 수 있다.
- 메인 에이전트의 최근 문맥을 활용하기 좋다.
- 과도한 알림보다 "조용한 유용함"이 중요하다.

### 문서상 의도

`AGENTS.md` 기준 heartbeat는 이런 용도에 맞다.

- 이메일, 캘린더, 멘션, 날씨 같은 가벼운 점검 배치
- 여러 주기 점검을 한 번에 묶어 API 호출 절약
- 사용자가 바쁠 때는 조용히 있기
- 새로 알릴 내용이 있을 때만 반응하기

현재 `HEARTBEAT.md`는 거의 비어 있으므로, 실제 운영은 heartbeat 중심이 아니라 cron 중심이다.

## 둘의 차이

### 1. 실행 기준

- `cron`: 시간 기준
- `heartbeat`: 상황 기준

`cron`은 "오전 8시", "10분마다", "매 1분"처럼 정해진 시점이 핵심이다.

`heartbeat`는 "지금 체크할 가치가 있는가", "새 소식이 있는가"가 핵심이다.

### 2. 실행 독립성

- `cron`: 독립 실행
- `heartbeat`: 메인 에이전트 루틴에 가깝다

`cron`은 개별 잡 단위로 기록과 상태가 남는다.

`heartbeat`는 독립 배치 작업이라기보다, 메인 에이전트가 자신에게 주어진 체크리스트를 돌며 상황을 보는 개념이다.

### 3. 결과 처리

- `cron`: 결과물을 만드는 경우가 많다
- `heartbeat`: 결과가 없으면 아무 말 안 하는 경우가 많다

예를 들어 `cron`은 뉴스 브리핑, 알림 메시지, 상태 보고서처럼 산출물이 뚜렷하다.

반면 `heartbeat`는 변화가 없으면 `HEARTBEAT_OK`처럼 조용히 종료하는 것이 정상이다.

### 4. 적합한 작업 유형

`cron`이 맞는 경우:

- 정시 실행이 중요함
- 독립 로그가 필요함
- 배포, 리포트, 알림처럼 결과물이 명확함
- 분 단위 반복 점검이 필요함

`heartbeat`가 맞는 경우:

- 여러 소소한 점검을 한 번에 묶고 싶음
- 정시에 딱 맞아야 할 필요는 없음
- 새 정보가 있을 때만 사용자에게 말하고 싶음
- 메인 에이전트의 최근 문맥을 반영하고 싶음

## 비유

- `cron`은 알람 시계다.
- `heartbeat`는 비서의 루틴 체크다.

알람 시계는 정해진 시간에 무조건 울린다.

비서의 루틴 체크는 "지금 중요한 게 있나?"를 보고, 없으면 조용히 넘어간다.

## 이 프로젝트에서의 실제 적용

현재 구조는 거의 `cron` 중심이다.

### cron에 잘 맞는 현재 작업

- 뉴스 게시판 매일 업데이트
- 업비트 이상 징후 점검
- 체결 발생 감지
- 변동성 알림

이 작업들은 시각 또는 짧은 간격이 중요하고, 독립적으로 수행되어야 하므로 cron이 적합하다.

### heartbeat에 더 잘 맞는 잠재 작업

- 오늘 일정 확인
- 긴급 메일 체크
- 오랫동안 사용자에게 전달할 변화가 없었는지 확인
- 여러 생활형 상태 점검을 한 번에 수행

이런 작업은 꼭 정시에 실행될 필요가 없고, 결과가 있을 때만 사용자에게 말하면 되므로 heartbeat가 적합하다.

## 운영상 주의점

### cron의 리스크

- 중복 실행
- 같은 파일을 여러 잡이 동시에 수정
- 과도한 알림 발생
- 실패한 잡이 계속 누적

이 프로젝트에서도 뉴스 보드 운영 문서에서 중복 크론과 배포 충돌을 주의하도록 되어 있다.

### heartbeat의 리스크

- 별일 없는데 너무 자주 반응
- 점검 기준이 모호해 일관성이 떨어짐
- 체크리스트가 비대해져 오히려 무거워짐

heartbeat는 "필요할 때만 말하기" 원칙이 중요하다.

## 결론

이 환경에서 둘의 차이는 명확하다.

- `cron`은 시간에 의해 트리거되는 자동 실행 시스템
- `heartbeat`는 에이전트가 주기적으로 주변을 살피는 점검 루틴

현재 `.openclaw`는 뉴스/트레이딩 자동화 중심이라 `cron`이 주력이고, `heartbeat`는 아직 거의 비어 있는 보조 메커니즘 상태다.
